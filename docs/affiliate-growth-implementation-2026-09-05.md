# Camp Gear Lab：購入前の判断を助けるサイト改修

## 目的と判断

検索で訪れた読者が、自分の条件を整理し、候補を比較して、販売店で価格・付属品を確認できる構成にする。成果の判定は確定報酬と同じ期間の送客データで行う。クリックやGA4のキーイベントを購入と見なさない。

先に共有された検索・閲覧・注文資料を参考に、既存のテント・クーラー記事に加え、家族の寝具と照明の周辺用品へ導線を広げる。少数の商品明細は継続需要の証明ではない。報酬額や原本CSV、個別アカウント情報はこの公開リポジトリに保存しない。

## 今回実装した範囲

| 領域 | 変更 | 狙い |
|---|---|---|
| トップページ | 冒頭から寝具・テント・照明・暑さ対策を選べる入口。新着記事を絞り、検索への入口を近づける | 記事名を知らない読者も選び始められる |
| 目的別ガイド | `/gear-guides` に購入前の確認点と読む順番を集約 | カテゴリ一覧と比較記事の間をつなぐ |
| 記事からの回遊 | 対象カテゴリの記事末尾から、対応する目的別ガイドへ戻れる | 寝袋からマット・枕など、関連する判断に進める |
| 販売店案内 | 商品カード・ランキング・比較表・記事上下の案内を共通化 | 重複リンクを減らし、価格・在庫の確認先を選びやすくする |
| 計測 | 既存クリック計測を補強。販売店リンクの表示とガイド移動をGA4へ追加 | 露出が少ないのか、表示されても押されないのかを分けて考える |
| 管理画面 | 記事 × 商品 × ボタン位置の一覧。取得上限に依存しないページ取得とエラー表示 | 集計欠落や取得失敗をゼロ件と誤認せずに改善箇所を特定する |

新しいガイドはコードで管理するページで、既存の公開記事にのみリンクする。記事が削除・非公開になった場合はリンクを除き、空になったガイドも表示しない。既存記事のURLと検索用の正規URLは維持する。ガイドをサイトマップ、ヘッダー、フッターに追加する。

Next.jsのサーバーコンポーネントと既存のISRを維持し、クリック・表示計測だけをクライアント側で扱う。追加のUIライブラリ、外部計測サービス、DBマイグレーションは不要。

販売店URLに含まれる既存のアフィリエイトIDは保持する。表示順は従来の方針を維持し、リンクのない販売店を除いた実際の順番を記録する。この順番が収益上最適と立証されたわけではない。商品名・価格・実測値・使用経験を今回新たに作り上げることはしない。

## 計測の定義

| イベント | 発火条件 | 主な項目 | 保存先 |
|---|---|---|---|
| `affiliate_offer_view` | 対象の販売店リンクが画面に半分以上入ったとき、マウントされたリンクごとに一度 | `product_id`, `merchant`, `placement`, `page_path`, `price_band`, `rank` | GA4 |
| `affiliate_click` | 販売店リンクをクリック | 上記に商品名・リンク先等を付加 | GA4と既存の自前クリック記録 |
| `guide_navigation` | トップ・ガイド・記事末尾の目的別リンクをクリック | `guide_id`, `placement`, `destination`, `page_path` | GA4 |
| `article_navigation` | 記事内ナビで目次・比較表・価格へ移動 | 前回実装の項目を維持 | GA4 |

表示イベントは折りたたみ内や画面外では発火しない。目視や読了、ユニークな人数を証明するものではない。戻る操作・再訪問などで再度表示される場合がある。本文のインラインリンクは表示イベントの対象外なので、ボタン表示との比較から除く。

GA4の準備前に発生した表示イベントは、既存タグの初期化まで上限付きで一時保持する。GA4の例外が購入リンクや自前記録を止めないようにし、sendBeaconが拒否されたときのみ同一オリジンのkeepalive送信へ切り替える。どちらの記録も通信やブロッカーによって欠落しうる。

自前のクリック記録は、記事・商品・販売店・位置の集計に利用する。表示回数はGA4だけに記録するため、クリックと表示を比較するときは両方ともGA4の値を使う。価格帯とボタン順は現状GA4のみで保存され、過去のサーバー記録から復元できない。

管理画面では期間の開始・終了を日本時間で表示する。DB取得は同じ期間末を固定し、ID順に続きを読み込む。途中で失敗した集計や上限を超える集計は、正常な部分集計として返さない。クリックの重複排除・売上推定は追加していない。

## GA4側で設定・確認すること

コードのイベント送信と、GA4管理画面の設定は別。GA4側への設定変更は今回実施していない。

1. 本番反映後、リアルタイムまたはDebugViewでイベント受信を確認する。
2. 管理 → データの表示 → カスタム定義で、必要なイベントスコープの項目 `merchant`, `placement`, `product_id`, `guide_id`, `destination`, `price_band` を確認し、未登録分だけ作成する。重複登録しない。
3. 探索でページパス・商品・販売店・位置ごとの `affiliate_offer_view` と `affiliate_click` を同じ期間で並べる。表示イベントが導入される前の期間を分母に混ぜない。
4. 閲覧・移動・外部リンククリックを一括で「購入」として設定しない。既存キーイベントの定義も確認する。

参考：[Googleのイベント送信仕様](https://developers.google.com/analytics/devguides/collection/ga4/events)、[カスタムディメンションの説明](https://support.google.com/analytics/answer/14240153?hl=ja)。DB取得上限の根拠：[Supabase select](https://supabase.com/docs/reference/javascript/select)。

## 次の制作と評価

| 順序 | 作業 | 完了条件 |
|---|---|---|
| 公開準備 | 作成済みの家族向けマット原稿を対象記事として登録し、品番の合う販売店リンクを照合する | Supabaseへの対象記事の登録・確認。gitのマージだけでは記事原稿は公開されない |
| 既存記事の改善 | 子供用寝袋・枕・LEDランタンの比較基準と既存商品情報を照合する | 対象者・注意点・仕様の根拠が記事とカードで一致する |
| 長い検索語への対応 | マットの配置、シェードの対応機種など、一つの判断に答える記事を追加する | 既存記事と役割が重ならず、公式資料か本人の確認済みの経験がある |
| 公開後の評価 | 同じ期間・記事・販売店で表示、クリック、確定成果を比較する | 季節性と集計期間の違いを分け、変更を続けるか判断する |

医師であることを商品の効果保証に使わず、家族での設営・積載・手入れなど、購入前に確かめられる具体的な判断を増やす。Xではその判断に答える記事を紹介し、クリック先との内容を揃える。Xへの投稿や外部の成果計測IDの発行は今回実施しない。

## 検証

- 公開記事のみのガイド生成、欠落時の非表示、販売店のリンク保持と実際の表示順をテスト。
- 取得上限を超えるクリック集計、途中の取得失敗、記事・商品・位置別の集計をテスト。
- GA4障害時の独立送信、ビーコン拒否時の代替送信、表示イベントの初期化待ち・表示閾値・重複防止をテスト。
- 既存テストを含む220件が成功。本番ビルドも成功し、目的別ガイドを含む静的生成を確認。
- 生成HTMLの6ページで見出し、移動先、ID重複防止、商品リンク属性を確認。ガイドの正規URL・サイトマップ・公開記事への接続、安全記事の冒頭CTA除外も確認。
- ブラウザ・実機での新しい表示検証、GA4本番受信、本番DBへの接続を伴う管理画面確認は未実施。
