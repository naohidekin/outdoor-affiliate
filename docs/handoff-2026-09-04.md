### モンベル公式の引き方（ヘリノックスもここ）

サイトマップは無いが、**検索はサーバ側で描画される**。パラメータは `top_sk`。

```bash
Q=$(python3 -c "import urllib.parse;print(urllib.parse.quote('チェアワン'))")
curl -sL --compressed -A "$UA" "https://webshop.montbell.jp/goods/list_search.php?top_sk=$Q"
```

商品ページは `https://webshop.montbell.jp/goods/disp.php?product_id=<品番>`。
`disp_fo.php` は**アウトレット枠**なので、そこにしか無い型番は旧世代とみなす。
`【素材】` 以降に素材・耐水圧・透湿性・重量・収納サイズが揃っている。

## 作法（前セッションで痛い目を見た分）

### データを書くとき

`data/` への書き込みは必ず `src/lib/stable-json.mjs` を通す。
**引数は `(filename, data)` の順**。逆にすると products.json が1行に潰れる。

```js
import { stableDataFileString } from './src/lib/stable-json.mjs';
fs.writeFileSync('data/products.json', stableDataFileString('products.json', products));
```

書く前に必ずコピーを取る。文字列置換は「一致数がちょうど1件」を assert してから
実行する。これで実際に3回、別製品への誤爆を寸前で止めている。

### 記事本文を直すとき

- 本文に H1（`# 見出し`）を書かない。H2 から
- `{{comparison:...}}` タグの中の製品IDも忘れず直す（本文だけ直して事故りかけた）
- 「◯製品を比較」のような件数表記と実際の掲載数を合わせる
- 価格は触らない（ユーザー判断・9/4確認済み）

### スクレイピングの型

Amazon も楽天も `--compressed` と `Accept` ヘッダと ブラウザUA が要る。
**楽天は EUC-JP** なので `charset` を読んでデコードする。

```bash
curl -sL --compressed -A "$UA" \
  -H "Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8" URL
```

PDF は `pypdf` が壊れている（`_cffi_backend` / pyo3 panic）。`pymupdf` を使う。
図面は `page.get_pixmap(dpi=170)` で PNG にしてから Read ツールで見る。

スノーピークは展開サイズ・インナー高が**取扱説明書PDFにしか無い**。
EC は品番ではなく内部SKU（`SNP0118A0266` 形式）でしか引けないので、
`ec.snowpeak.co.jp/sitemap_item/sitemap_item_0.xml` を巡回して当てる。

### 判断のしかた

**「カタログに無い」は廃番の証拠にならない。** GST-120R はクロールに出て
こなかったが現行品だった。実在しないと結論できたドライネットは、
独立した5つの出典が揃って否定した場合だけ。

内部データの整合チェックでは主要な誤りは見つからない。
「別製品の数値が混入している」が最頻の誤りで、これは公式と突き合わせないと出ない。
その記録は台帳末尾の「スペック誤りを機械的に洗おうとして失敗した記録」にある。
