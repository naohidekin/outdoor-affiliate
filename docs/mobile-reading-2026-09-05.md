# スマートフォンの読みやすさ改善（第2弾）

記事を検索から開いた読者が、内容を読み、比較し、販売店へ進みやすい表示に整えた。既存のNext.js/Vercel構成で実装している。

## 変更

- 記事冒頭はタイトル・著者・更新日、比較画像、目次の順に整理。目次は冒頭の商品案内より前に置き、見出しへ直接進める。
- Markdown本文だけに `.prose` を適用。従来のCSSは `.not-prose` の商品カードにも及び、写真の余白・リンク色・表の幅を上書きしていた。商品コンポーネントを本文装飾の範囲から分離した。
- 本文の17pxは維持し、スマホの大見出しを22pxからの可変サイズに変更。商品説明は16px、仕様と購入ボタンは14pxを基本にした。
- Markdown表と商品比較表を共通の横スクロール領域で包む。先頭列を固定し、横に動かせる案内、キーボードフォーカス、商品表の行・列見出しを追加。ページ全体を横スクロールさせない。
- 商品の選定理由を写真脇の狭い列から出し、カード幅で読める配置に変更。購入ボタンは高さ44px以上。ランキングの順位表示で商品名の横幅を圧迫しない。
- 商品写真に重なる回転スタンプを小さなセール案内へ変更。日付判定と表示内容は維持。
- スマホの記事カードは小さな写真と全文タイトルの横並びに変更。PCは画像付きグリッドを維持。
- 記事一覧はスマホのカテゴリチップ群を選択欄に変更。検索・カテゴリの組み合わせ、結果件数、条件のクリアを用意。入力欄は16px、メニューボタンも44px以上。

## 検証

ローカルJSONを使い、Chromiumの同一オリジンiframeでCSSの画面幅を切り替えて確認した。実機のタッチ操作やSafariのエミュレーションではない。

| 対象 | 確認内容 |
| --- | --- |
| 記事一覧 | 320・375・390・428・768・1280pxの表示。320・390・428・768・1280pxでは文書のclientWidthとscrollWidthが一致 |
| トップページ | 320pxで見出し、本文、主要リンク、季節案内を目視確認 |
| ランドロック比較 | 320・375pxで目次と比較表、1280pxで本文・表を目視確認。目次から見出しへ移動し、横操作で別モデルが見えても項目列が残ることを確認 |
| 子供用寝袋 | 390pxで商品カードの説明、仕様、販売店ボタン、本文へのつながりを目視確認 |
| 操作 | スマホのカテゴリ選択で21件、キーワード「ランドネスト」の併用で4件、クリアで117件に戻ることを確認。メニュー開閉とEscapeによる閉じる操作を確認 |
| 購入ボタン | ランドロック記事の楽天ボタン5件で14px・高さ44pxをDOM測定。販売リンクの遷移・購入は行っていない |

既存の203テスト、本番用ビルド（型チェックを含む・188ページ生成）、`git diff --check`を実施。本番Supabaseのデータ、実機Safari、一部外部メディアの表示は公開環境で別途確認する。原稿の医師・著者確認状況は変更していない。

## 開発用プレビュー

`scripts/dev-server.mjs` は通常のNext.js開発起動を保ち、プレビュー用の `--host` を `--hostname` へ読み替え、未対応の `--strictPort` を除く。`next.config.ts` の `allowedDevOrigins` にプレビュー用ホストを一つ指定した。未指定ではNext.jsが開発用リソースを遮断し、検索・メニューが動作しなかった。設定後に両方の操作を確認できた。この設定は開発サーバーにだけ適用される。[Next.jsの説明](https://nextjs.org/docs/app/api-reference/config/next-config-js/allowedDevOrigins)。

検証用HTMLは削除し、リポジトリに含めていない。新しい依存パッケージは追加していない。
