# 楽天ウェブサービスへの問い合わせ下書き（2026-08-23 作成）

`scripts/check-rakuten-api.mjs` を実行して**全アプリ・全条件で失敗した場合**に送る。
新規アプリだけ通ったなら送る必要はない（載せ替えれば済む）。

送り先: https://webservice.faq.rakuten.net/hc/ja/requests/new
（FAQ「利用規約に違反しているか個別に確認をしたい」と同じ窓口）

---

## 書くときの方針

- **こちらの落ち度を先に書く。** レート制限違反を実際にしていた。
  隠して問い合わせると、向こうがログを見た時点で心証が悪くなる。
  修正済みであることを添えれば、むしろ再発防止の意思が伝わる
- **「復旧してください」ではなく「状態を教えてください」と聞く。**
  停止処分なのか障害なのかで、こちらのやることが変わる。
  それを確定させるのが問い合わせの目的
- 推測を断定で書かない。事実（エラー文言・日時・再現条件）だけを並べる
- アクセスキーは書かない。アプリIDは向こうが特定に必要なので書く

---

## 本文（コピーして使う）

件名: application_id が API Configuration not found を返す状態について

いつもお世話になっております。
楽天市場商品検索API（IchibaItem/Search/20220601）の利用について、
現在の状態をご確認いただきたくご連絡しました。

■ 発生している事象

2026年8月23日より、下記エンドポイントへのリクエストが
すべて `API Configuration not found` を返す状態が続いています。

  https://openapi.rakuten.co.jp/ichibams/api/IchibaItem/Search/20220601

■ 対象の application_id

  （1つ目のアプリID）
  （2つ目のアプリID）

■ こちらで確認済みのこと

- 管理画面でアプリケーションは有効な状態として表示されています
- 楽天市場商品検索APIが利用可能な設定になっていることを確認しました
- 現在のグローバルIPアドレス（   ）はIP許可リストに登録済みです
  （所属レンジ    /24 も登録しています）
- accessKey の有無、リクエストヘッダの有無、エンドポイントの違い
  （app.rakuten.co.jp 側も含む）で条件を変えて試しましたが、
  すべて同じエラーになります
- 上記2つのアプリケーションで同じ結果になります

■ こちらの規約違反について（先に申告します）

弊サイトのスクリプトに、リクエスト間隔が1秒未満になる箇所が
3か所あったことを確認しました。「1つのapplication_idにつき
1秒に1回以下」の制限に反しており、こちらの不備です。
発見後ただちに修正し、現在は全経路で1.2秒以上の間隔を
確保しています。

2. 停止であれば、解除のために必要な手続き
3. 停止でない場合、他に確認すべき設定があればご教示ください
