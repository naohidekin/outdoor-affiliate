## 今日いちばん大きかった発見

### 1. 楽天APIが10日間止まっていた

エンドポイントのバージョンが `20220601` のままで、楽天は `20260701` に
移っていた。古いほうは `API Configuration not found` を返す。この文面が
認証エラーに見えるため、切り分けに丸1日かかった。

同じURLが12ファイルに直書きされていて、**全部同時に死んでいた**。
`audit-prices` / `check-market-prices` / `check-duplicate-prices` /
`verify-links` / `article-product-agent` / `src/lib/product-lookup` など。
価格監査もリンク検査も無言で失敗し続けていた。

再発防止に `npm run check:rakuten`（`scripts/preflight-rakuten.mjs`）を作り、
日次パイプラインのキルスイッチ判定の直後に入れた。止めずに続けるが、
失敗を大きく出す。CLIENT_IP_NOT_ALLOWED のときは現在のIPと「貼る2行」まで出す。

**教訓**: 定期実行が静かに失敗する経路を疑うこと。

### 2. 成果報酬の上限（楽天アフィリエイトガイドライン 2025/6/26）

> - 成果報酬の上限は、**1商品1個の売上につき1,000円**
> - 同一のユーザからの購入に基づく成果報酬は、**1ユーザあたり月3,000円**

対象は楽天市場・各ショップ / 楽天ブックス / kobo / 楽天ビック / Edy /
Rakuten Fashion / 楽天24。料率は 2%〜4%（商品ジャンル別）。
スポーツ・アウトドアはCSVを見る限り全件4.0%。
楽天トラベル・GORA等のグループサービスは上限の記載が無く、実測でも
¥154,000 の予約に ¥1,540 が満額で付いている。

**収益設計の結論**: 読者1人あたりの最適解は「**¥25,000以上を3点**」
（¥1,000×3 = 月上限¥3,000に到達）。中単価を並べると同じ¥3,000に届くのに
倍の点数が要る。当初「中単価を厚く」と書いたのは誤りで、訂正済み。

上限は商品ごとなので、高額品に中単価を足しても**カニバらない**。

### 3. 楽天収益の7割はキャンプ由来ではない

規約第9条6項に「リンク先の商品と成果対象の商品は必ずしも一致しない」と
明記されている。読者が記事のリンクを踏んだ後にした自分の買い物も計上される。

2026-08 の内訳: スポーツ・アウトドア ¥3,801（26.8%）/ 楽天トラベル・GORA
¥3,591（25.3%）/ 家電・楽器・美容ほか ¥6,813（47.9%）。合計 ¥14,205。
Amazon は ¥14,120（クリック1,542・返品0）。**8月合算 ¥28,325**。

全体は7月比+31%だが、**キャンプ由来は−25%**。増分は楽天トラベル¥154,000の
予約とポータブルエアコン。総額だけ見ると効果を取り違える。

分析は `npm run report:rakuten -- <注文明細CSV...>` で再現できる。

### ③ アメニティドームS の価格（`tent-duo-002`）

登録 ¥44,000 は実勢からかけ離れている。Amazon の S アイボリー
（`B0BCQ6DJTB`）が ¥30,101。削除した重複レコードの値が混ざったもの。

`tests/spec-consistency.test.ts` の `KNOWN` に「S > M の逆転」が残っている。
直したらそこから消す。

`audit-prices` が出した94件の「要目視」は、実売/登録の中央値が105%だった
ことから**大半が別商品の誤検出**と考えられる。全部当たる価値は低い。

### ⑦ 楽天の計測ID発行（あなたの操作。測定の土台）

69件の注文のうち計測IDが入っていたのは楽天ROOMの1件だけ。サイトのリンクには
付いていない。楽天は「リンク先と成果対象は一致しない」と規約で宣言している
ので、ジャンルでの推定には原理的な限界がある。

**注意**: `CLAUDE.md` の「`ut={トラッキングパラメータ}`」は**誤り**。
デコードすると `{"page":"item","type":"text","size":"240x240",...}` で、
リンクの見た目の設定だった。計測とは無関係。修正が要る。

`rafcid=wsc_i_is_<UUID>` は3種類あり、`campgearlab商品検索` の
アプリケーションIDと一致する。過去のリンク生成はこのアプリで行われていた。

発行できたらリンクを1本もらえば、378件への一括付与スクリプトを書ける。

## この案件で守ること

- `naohidekin/outdoor-affiliate` は**公開リポジトリ**。鍵の値をコミットしない
- `.env.local` はMacにしかない。チャットに値を出さない
- `git checkout -- .` と `git checkout -- data/` は使わない
  （`price-history.json` が消えると価格推移を復元できない）
- 同期は `npm run db:sync -- --no-pull`。`--skip-git-check` は使わない
- `data/products.json` を書くスクリプトは `updatedAt` を必ず進める
  （進めないと `db:sync` に反映されない）
- `audit-prices --apply` は正規化せずに書く。あとで `npm run data:normalize`
- 管理画面での削除とJSONからの削除は**両方**やる。片方だけだと同期で復活する
- データ・ファイル・本番への変更は実行前に必ず確認を取る（`CLAUDE.md` ルール3）
