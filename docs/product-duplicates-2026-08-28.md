# 重複商品の整理（2026-08-28）

商品392件を突き合わせて重複を洗った結果。**重複そのものより、
重複ペア間でスペックが食い違っている問題のほうが重い。**

`db:sync` は upsert のみで削除しないため、`data/products.json` から
消してもSupabaseには残る。**削除は管理画面から行う必要がある。**

---

## 0. 確認して直した（2026-08-30）

スノーピーク公式で確認し、**公開中の数値が誤っていた**ことが分かった。

| | 公開されていた値 | 公式 |
|---|---|---|
| 焚火台L 板厚 | 2.5mm | **1.5mm** |
| アメニティドームM 対応人数 | 4〜5人用 | **3〜5名**（快適な目安 3〜4名） |

**記事同士も矛盾していた。** 焚火台Lは本文で2本が1.5mm、1本が2.5mm。
アメニティドームMは本文が「定員3人」で、同じページのカードが「4〜5人用」。
読者は本文とカードを並べて見るので、その場で気づく状態だった。

商品データ2件と記事本文12箇所を公式の値に統一した。
`tests/spec-consistency.test.ts` が以後これを固定する。

アメニティドームMの記事は「Mは3人家族向け、子供2人ならタフワイド」という
論旨だった。公式が3〜4名を推奨している以上、この結論は**スノーピークより
厳しい見方**になる。数値を書き換えて論旨を隠すのではなく、公式の値を先に
示したうえで「僕はそれでも余裕がないと思う」と書き分けた。

## 1. 公式で確認して直した（2026-08-31）

ネットワークポリシーが Custom に広がり、**メーカー公式に到達できるように

## 1e. 積み残していた判断事項を片付けた（2026-09-04）

8/31に「数値の直しでは済まない」として残した2件と、細かい3件を処理した。

### `single-burner-ranking`：4台中3台の重量が誤っていた

「山に持っていくなら本体100g以下が目安です」として4台を挙げていたが、
**合っていたのは1台だけ**だった。

| | 記事 | 公式・正規品 |
|---|---|---|
| SOTO ウインドマスター SOD-310 | 67g | **67g ✓** |
| ユニフレーム US-D II | 62g | **約880g** |
| スノーピーク GST-120R | 73g | **56g** |
| プリムス P-153 | 75g | **116g** |

出典は SOTO公式（soto.shinfuji.co.jp）、スノーピーク公式楽天店、
イワタニ・プリムス正規品ページ。100g以下に収まるのは56gと67gの2台だけで、
P-153は116gあるので前提から外れる。

**US-D II はカテゴリごと違っていた。** 実物はCB缶の卓上バーナーで、
記事は「OD缶バーナー6選」の5番目に置き、OD缶の比較表にも入れていた。

削除ではなく**CB缶セクションへ移した**。製品自体は実在する良いバーナーで、
間違っているのは置き場所だけだったため。

```
変更前: OD缶6選（1-6） / CB缶3選（7-9） / システム2選（10-11）
変更後: OD缶5選（1-5） / CB缶4選（6-9・US-D IIは9番） / システム2選（10-11）
```

タイトルの「11選」は変わらない。商品データも8項目直した
（GST-120Rの重量・火力・収納、P-153の重量・火力・収納・ゴトク径・点火方式）。

`tests/spec-consistency.test.ts` に3件追加した。とくに
**「100g以下」と書いた段落から重量を拾って、全部100g以下かを機械で確かめる**
テストを入れた。数字を書き換えたときに前提が崩れるのを防ぐため。

// 前回同期済みだがSupabaseに存在しない → 管理画面で削除された

# Yahoo!ショッピングの導線について（調査メモ）

## 私の最初の見立ては誤りだった

`yahooUrl` にアフィリエイトパラメータが無いのを見て「1円も生んでいない」と
判断しかけたが、これは誤り。

`src/app/layout.tsx` にバリューコマースの **LinkSwitch**（`vc_pid`）が
設置されていて、コメントにも明記されている。

> バリューコマース LinkSwitch: shopping.yahoo.co.jp への直リンクを
> クリック時にアフィリエイトリンクへ自動変換する

URLにパラメータが無いのは、**クリック時にブラウザ側で変換する仕組みだから**で、
それが正常な形。URLの見た目だけで収益化の有無を判断したのが間違いだった。

`src/lib/trackAffiliateClick.ts` も `shopping.yahoo.co.jp` を "yahoo" として
計測している。仕組みとしては通っている。

## 残る本当の論点は「着地先」

| | |
|---|---|
| 公開記事に載る商品でYahooリンクあり | 290件 |
| うち**検索結果ページ**へ行く | **289件** |
| 商品ページへ行く | 1件 |

読者は「Yahoo!で見る」を押すと検索結果に着地し、そこから自分で商品を
探すことになる。商品ページへ直行する楽天・Amazonと比べて、
購入まで到達する割合は落ちるはず。

しかも導線としてはほぼ重複している。

| | |
|---|---|
| 掲載商品 | 309件 |
| 楽天リンクあり | 304件 |
| Amazonリンクあり | 288件 |
| **Yahooだけが導線** | **1件**（`dry-net-snowpeak`） |

## 判断が要ること

3つ目のボタンが、収益を足しているのか、それとも楽天・Amazonへの
クリックを削っているのかは、データを見ないと分からない。

決着させる方法はある。

1. GA4 の `affiliate_click` を `merchant` 別に集計し、Yahooの比率を見る
2. バリューコマースの管理画面で、同じ期間の確定報酬を見る
3. 「Yahooのクリック数に対して、報酬がどれだけ出ているか」を
   楽天・Amazonと比べる

Yahooのクリック比率が高いのに報酬がほぼ無いなら、検索結果への着地で
落ちている。その場合の選択肢は、商品ページURLに貼り替えるか、
ボタン自体を外すか。

**`dry-net-snowpeak`（スノーピーク テーブルドライネット UG-370 ¥5,500）
だけは、Yahoo検索が唯一の導線**なので、楽天かAmazonのリンクを
入れておきたい。

# スペック誤りを機械的に洗おうとして失敗した記録（2026-08-30）

アメニティドームMの重量が別製品からの混入だったので、同じ形の誤りが
他にもあるはずだと考えて検査を書いた。**ほぼ失敗した。** 同じ回り道を
しないように残す。

## 効かなかった検査

### 「別製品と重量が同値なら混入を疑う」

5.2kg がパセコの石油ストーブと一致していたので筋が良さそうに見えた。
32件を「疑わしい」と出したが、中身はほぼ雑音だった。

```
小数つき重量を持つ商品   108件
異なる値の種類            76通り
重複している値            20通り
```

**108件を76通りに入れるのだから、一致は起きて当たり前。**
2.7kg も 1.7kg も 3.6kg も、複数の製品が普通に持つ値だった。

### 「耐水圧が別製品と同値」

1,500mm / 2,000mm / 3,000mm は業界の標準値。一致して当然で、
最初から指標にならない。

### 「シリーズ内で大きいのに軽い」「収納サイズ ≧ 展開サイズ」

どちらも検出0件。悪くない検査だが、今のデータでは何も出なかった。

## 効いた検査

### シリーズ内の大小逆転（価格・重量）

出たのは2件だけで、うち1件は既知の重複ペア。残る1件は本物だった。

```
アメニティドーム S  tent-duo-002  ¥44,000
アメニティドーム M  tent-002      ¥42,900   ← Sのほうが高い
```

しかも **¥44,000 は重複レコード `tent-sp-amenity-dome-m` の価格と同じ**で、
**Sの室内高120cm も、その重複レコードが持っていた値と同じ**。
値が混ざった痕跡がここにも出ている。

`tests/spec-consistency.test.ts` に常設した。未確認の1件は KNOWN として
記録し、新しい逆転が出たら落ちる。

### 数値であるべき欄に定性表現

```
first-aid-burn-aid           サイズ「複数サイズ入り」
first-aid-poison-remover     サイズ「コンパクト・軽量」
rw-002                       収納サイズ「スタッフサック付属」
heatstroke-neck-cooler-kids  重量「軽量設計」
```

DODの「サイズ: 手のひらサイズ・コンパクト」と同じ形。誤りではないが、
比較表に出すと情報にならない。

## 結論：内部データだけでは見つからない

今回見つけた誤り（板厚・定員・重量・収納サイズ・価格・電源）は、
**すべてメーカー公式と突き合わせて初めて分かった。** 内部の整合性検査で
拾えたものは一つもない。

そしてこの作業環境からは**メーカー公式に到達できない**。18ドメインを
試して全滅した（プロキシが CONNECT に 403 を返す）。

```
snowpeak.co.jp / ec.snowpeak.co.jp / montbell.jp / coleman.co.jp
uniflame.co.jp / logos.ne.jp / dod.camp / ogawa-campal.co.jp
captainstag.net / nanga.jp / goldwin.co.jp / iwatani.co.jp
fish.shimano.com / daiwa.com / ecoflow.com / muranokajiya.jp
waq-online.com / sotolabo.co.jp
```

**スペック検証は人手でしか進まない。** 環境のネットワークポリシーを
広げれば自動化できる（claude.ai/code の環境設定）。
