# AI通知の読みやすさ・操作入口（2026-11-13）

本人の修正依頼に基づく共通設計。現在の実装対象は Camp 編集処理の確認通知のみ。他AI・他プロジェクトへ適用済みという意味ではない。

- 見出しで「状況共有」「本人の判断が必要」「処理が停止」を区別する。
- 内部エラーコードや内部IDではなく、対象名、平易な日本語の理由、次にできることを示す。
- 原因が不明なら推測せず、何を調べる必要があるかを伝える。
- 確認先は実在・検証済みリンクだけを示す。下書きの未公開URLを推測しない。
- 回答・修正の入口と短い返信例を付ける。ボタンを付ける場合は実装済みの受付先・対象版への拘束が必要。飾りのボタンや「押せば直る」といった未実装の約束はしない。
- 本人の承認が必要な操作、AI側の技術調査、情報共有を混同しない。
- 詳細ログは内部記録に保ち、承認制御・重複防止・不明結果の保留を弱めない。

## 今回の変更

`attention_presentation.py` で既知理由を日本語化。対象記事名と商品の未確認項目を残し、既存SlackスレッドのURL・メンション方法・具体的依頼文を付けた。未知理由の原文は表示せず未確認と伝える。配信キーや副作用制御は不変。既存通知を自動再送・書換しない。

テストは外部サービスを呼ばない。実際の新通知の読み戻し、Mac Proへの配備、他AI通知の統一は別途確認が必要。
