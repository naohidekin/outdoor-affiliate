# Camp editorial manager

このファイルの実体から `parents[2]` をリポジトリのルートとして解決する。
インストールは正本のこのフォルダへのsymlinkとし、リンク先の実体から解決する。
対象の `AGENTS.md` と [管理API・接続手順](../../docs/editorial-manager.md) を読む。
Astraへ渡す指示は [prompt.md](references/prompt.md) に置く。既存CLIの実コマンド、
認証、モデル指定、共有クレジット保護はMainが確認したmanaged adapterを使う。
スキルの設置だけではtickや本番への接続が完了したことにならない。

SQLiteが正本。`scripts/editorial/manager.py` は既存 `Runtime.tick` のruntimeロック内、
イベント・承認・公開処理の後、従来の自動生成分岐の前に一度だけ評価する。
管理有効時は従来の自動生成分岐と二重実行しない。独立daemon・並列producerを作らない。
未設定の予算でモデルを呼ばない。意味状態が同じなら、失敗・接続先変更後も再評価しない。
不明な実行結果は照合し、再送・再生成・カウンタ初期化で解決しない。
無効化・決定済み・旧版の送達記録だけを未確定の公開effectと混同せず、実行可能な候補を
非阻害的な過去診断より優先する。実際のunknown effectは対象ジョブを止め、journalを削除しない。

Astraは議題を選ぶだけ。Claudeの調査・構成・品質審査とGeminiの確定仕様内の推敲は維持する。
管理判断は本人承認でも品質審査でもない。本文変更は旧承認を無効にし、既存の全ゲートを通す。
商品仕様・価格・在庫・体験談・冬季性能・購入実績は、根拠なしに追加・外挿しない。

状態は検証済みGA4/GSCの期間・欠損・取得範囲、台帳のジョブ・効果・送達と限定された
状態receiptから読む。生検索語・個人本文・owner・nonce・認証情報をモデルへ渡さない。
既存公開記事の改善は検証済み候補URLまたはexact job/revisionに束縛した提案キューへ渡し、
公開DBや原稿を直接変更しない。訂正資料のprivate attachmentもMainの限定APIに任せる。

制作期・初回起動・期限・ジョブ件数・保持枠・承認・保留・再開・公開状態は、
入力された最新の台帳・設定・検証済み出典から判断する。日付付きの過去観測を現在状態にしない。
金曜09:00 JST・金〜木の制作方針も現在のproductionScheduleを先に確認する。
設定の任意項目initialTargetPublishByは本人承認を条件とした目標であり、自動公開権限ではない。
エラー・保留ジョブの枠を別ジョブ作成で迂回せず、訂正・再開は現在の根拠と既存ゲートに従う。
公開済みと束縛確認された版を再投稿しない。矛盾があれば状態を勝手に書き換えず照合する。
Buffer等の接続・キュー状態は現在の入力と検証証拠に従い、未取得を空キューと扱わない。
接続状態が変わっても管理判断にBuffer書込権限はない。
月曜20時・木曜20時・毎月5日20時の既存reporterを維持し、管理側から重複通知しない。

完了報告では、接続済みか未接続か、正本の状態、選択した議題と対象、ゲート結果、
未確認事項を区別する。要求モデル名を実モデルIDの証明に使わず、返却IDがなければnull、
実請求USDがなければnullとして費用欠損を残す。ChatGPTクレジットをUSDへ換算しない。


公開確認済みの対象版は、既存runnerの `indexTracking` で公開サイトマップのURLと
実際の更新日時を照合し、Search ConsoleのURL検査を行う。公開直後の初回に続き、
サイトマップ反映または登録を確認できないときは翌日・7日後に再確認する。
既存記事の明示的なバックフィルは初回検査から起算する。
サイトマップ掲載、Googleの登録判定、最終クロール時刻、認証・取得不能を区別する。
URL検査は読み取り専用で、公開・SNSの承認やGoogleへの登録リクエストは行わない。
結果は対象版ごとの `index-tracking` 受領情報と `health.json` を確認する。
